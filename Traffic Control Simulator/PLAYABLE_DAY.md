# Кампания мэра

Ветка: `codex/playable-day`. Проект предназначен для Unity 2022.3.7f1.

## Запуск

1. Открыть `Assets/_Project/Scenes/Production/Bootstrap/BootstrapScene.unity`.
2. В Play Mode Bootstrap открывает главное меню кампании.
3. Выбрать новую кампанию и подтвердить замену текущего сохранения. Предыдущий основной save сохраняется как `.bak`.
4. В подготовке смены нажать «Начать смену» и регулировать светофоры.
5. По окончании таймера мир останавливается, результат записывается и отображается вместе с изменением доверия и новостью.
6. Продолжить следующий день. После последнего дня показывается исход выборов.

`Esc` ставит смену на паузу. Выход посреди смены возвращает к началу этого дня при следующем продолжении. Обучение не записывает результаты в кампанию. Старый экран выбора уровней доступен отдельной кнопкой в меню; его исходные Canvas сохранены и временно скрываются только в меню кампании.

## Что реализовано

- Подготовка, игра, пауза, однократные итоги и следующий день.
- Реальный учёт проездов через PathEnd с защитой от нескольких коллайдеров и повторного триггера на одну машину.
- Регистрация существующих и вновь созданных RTC-машин.
- Оценка времени остановок: скорость ниже 0,5 м/с дольше двух секунд. Это среднее накопленное время сверх двухсекундного порога по созданным машинам, а не измерение всех дорожных очередей и входящего спроса.
- Прежняя формула очков и репутации, вынесенная в проверяемые чистые правила.
- Кампания с конфигурируемой длиной и сохранённым исходом выборов. Значения по умолчанию: 7 смен, старт 50, порог 60.
- Валидация и миграция прежнего сохранения, резервная копия, запись через временный файл и File.Replace. Ошибка записи оставляет текущий прогресс в памяти прежним и позволяет повторить сохранение результата.
- Минимальные игровые экраны через runtime IMGUI. Они доступны в пользовательской сборке, не требуют Debug Panel.
- Рабочие сцены и шаблон получают Campaign Entry. В сценах без городских компонентов необходимые системы создаются при запуске.

Файлы сохранения: `Application.persistentDataPath/save.json`, `save.json.bak`. Если основной файл повреждён, проверяется резервный. Если оба непригодны, файлы остаются на диске до явного старта новой кампании. Продолжение при этом недоступно. Успешный результат дня публикуется в живые данные только после записи файла.

Физические контакты машин считаются авариями только при включённом `CountVehicleCollisions`. По умолчанию флаг выключен: сценарий аварий и допустимые контакты ещё требуют игрового решения. При включении пара автомобилей учитывается однократно за смену, даже если событие приходит от обоих участников.

## Настройки

`Traffic Control / Select / Game Settings`:

- Day Duration Seconds — длительность смены.
- Campaign Length Days — количество дней до выборов.
- Starting Reputation и Election Threshold — начальное доверие и порог.
- Spawn Interval Multiplier — множитель паузы между машинами.
- Параметры формулы очков и штрафов.
- Gameplay/MainMenu/Tutorial/LevelSelection Scene Path — маршруты экранов.

Следующий день повторяет текущую карту с новой статистикой. Отдельное расписание спроса для каждого дня пока не реализовано. Изменение GameSettings в Play Mode сохраняется в asset. Короткие тестовые значения нужно вернуть перед коммитом; изменение длины срока посреди старой кампании может потребовать новой игры.

## Автоматические проверки

Из корня репозитория, с установленным .NET 8 SDK:

```powershell
dotnet run --project "Traffic Control Simulator/Tools/CampaignTests/CampaignTests.csproj"
```

18 проверок используют реальные исходники чистых правил и записи файлов: формула, неизменность исходного состояния до commit, повторное завершение, победа/поражение, граница 59/60, пределы репутации, независимость истории, миграция, отклонение неверных данных, резервная копия и неудачная запись. Файловые тесты создают отдельную временную папку и не трогают игровое сохранение.

## Обязательная проверка в Unity

Полная компиляция проекта и Play Mode в Unity 2022.3.7f1 пока не выполнены. Изменённые скрипты отдельно скомпилированы против установленных Unity 6 API с проверочным RTC-контрактом. Это не проверяет физику и полную интеграцию стороннего RTC.

Пройти меню, подготовку, несколько проездов, паузу, конец таймера, повторное сохранение при отказе записи, следующий день и продолжение после перезапуска. Проверить, что обучение не меняет кампанию, а результаты доступны без Editor-окна. Проверить UI на целевых разрешениях и ссылки собственных/сторонних префабов.

Дальше: настройка баланса полного срока, различные сценарии спроса, обучение механикам, окончательный UI, правила аварий, внешнее игровое тестирование и профилирование. Версия является первым функциональным срезом кампании, готовность к релизу не заявляется.
